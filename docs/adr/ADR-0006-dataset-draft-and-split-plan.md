# ADR-0006：数据集草稿、决策账本与稳定切分计划

- **状态**：已接受（首阶段落地）
- **日期**：2026-11-05

## 背景

训练页的“本批生成”原来只写浏览器 `localStorage`，不会传入 Stage 3。SFT 准入和 train/eval 项目映射则在每次 Stage 3 运行时临时计算；新增项目可能改变已有项目归属，用户也无法持久排除某条 SFT 样本。`03_train/` 同时包含当前合成、历史修订和交付格式，不能充当唯一决策账本。

产品仍坚持模型质量判断为主、人工步级/样本级编辑为辅，不恢复全量人工审批。

## 决策

1. **数据集草稿是训练页的默认工作视图。** 草稿展示将要生成的候选样本、自动准入结果、split 与排除原因；构建按钮消费同一份草稿决策，而不是重新采用另一套选择。
2. **人工样本决策进入服务端账本。** `exclude` 跨重建保持，`auto` 撤销人工排除并恢复自动质量门禁。浏览器只保存筛选和分页偏好，不保存入集事实。
3. **切分计划持久化。** 首次可导入现有 `stats.json` 的项目归属；此后已有项目不因新增项目或普通重建而移动。用户可固定单个项目，也可显式重规划比例和 seed。
4. **所有产物共用项目级 split。** SFT、完整轨迹和 DPO 不得把同一 `project_group` 拆到不同集合。
5. **预览与构建复用同一 SFT planner。** 首阶段覆盖 SFT 单步窗口和完整轨迹的候选、排除、恢复及差异统计；DPO 保留现有模型复核与排除账本，稳定 split 对其生效，但不声称首阶段已经统一 DPO 评估预览。
6. **构建记录草稿指纹。** 指纹覆盖配置、切分、决策和 SFT 构建内容，用于显示“自上次构建后有变化”；首阶段不把该指纹宣称为完整不可变 release manifest。
7. **旧行为兼容。** 既有 `dpo_exclusions.json` 继续生效；通用账本中的新决策优先于旧 DPO 账本。已有 Stage 3 API 保持入口不变，内部改为消费稳定切分和草稿决策。

## 后果

- 训练页可以真实回答“这条样本是否将进入下次构建、为什么、如何撤销排除”。
- 普通重建不再因项目列表变化而隐式移动 train/eval。
- 首批实现不是完整 Build/Release 版本系统：不可变构建目录、统一 DPO 评估预览和按 Build 打包仍需后续 ADR/实现。
- 变更 `unreviewed` 或 `needs_human` 的自动准入口径不在本 ADR 范围内，仍由 ADR-0001 约束。
